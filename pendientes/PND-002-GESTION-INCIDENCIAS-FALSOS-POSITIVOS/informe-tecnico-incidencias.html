2. Incidencia 1: FortiGate Border1 (VPN OID Data Unavailable)

Ref: Host 10697 • Trigger 38674

2.1. Diagnóstico Forense de la Falla

El canal de Telegram de redes alertó: "P3 PREVENTIVO | Warning | FortiGate border1: Legacy static VPN OID data unavailable" con datos en estado *UNKNOWN*. La investigación técnica determinó que coexistían dos reglas de descubrimiento para túneles VPN:

  • Regla Legada Inválida (Item 60782): Descubría nombres de interfaces mediante IF-MIB::ifName (OID 1.3.6.1.2.1.31.1.1.1.1) pero luego intentaba consultar la tabla propietaria de Fortinet 1.3.6.1.4.1.12356.101.12.2.1.1.3.{#SNMPINDEX}. Al no concordar los índices, el firewall devolvía error SNMP No Such Instance. Los 10 items cayeron en estado Not supported y dispararon la alerta por nodata(30m) = 1.
  • Regla Oficial Operativa (Item 51382): La regla nativa vpn.tunnel.discovery ya monitorea con éxito y en tiempo real el tráfico y estado de todos los túneles IPsec (sap-pri, sap-bkp, anielo1, anielo2, ros1sj1).

2.2. Acciones Ejecutadas & Comentario Registrado en Auditoría

Se ejecutó el reconocimiento formal y la desactivación del trigger y de la regla legada:

Comentario de Auditoría en Zabbix (Evento 174446793):
"Falso positivo verificado. El monitoreo de túneles IPsec en este FortiGate opera correctamente a través de la regla LLD oficial 'vpn.tunnel.discovery' (OIDs privadas FortiOS). La regla legada 'ipsec.tunnel.discovery' y el trigger 38674 consultaban OIDs sin instancia activa. Se procede al cierre y desactivación del trigger." 
// Comandos ejecutados vía initMAX Zabbix MCP Server:
event.acknowledge({ "eventids": ["174446793"], "action": 6, "message": "Falso positivo..." });
trigger.update({ "triggerid": "38674", "status": "1", "comments": "Deshabilitado: Falso positivo..." });
discoveryrule.update({ "itemid": "60782", "status": "1" }); // Detiene sondeo SNMP erróneo

3. Incidencia 2: Storage HPE MSA 2060 (Service Down or Unavailable)

Ref: Host 10727 • Trigger 29355

3.1. Diagnóstico Forense y Descarte de Falla de Hardware

El canal crítico Alertas-Guardia-P1 notificó una alarma de severidad High (P1) para la cabina SRO-STO02. Ante el riesgo potencial sobre la operación del datacenter de Rosario, se realizaron pruebas de contraste inmediatas:

  • Disponibilidad Física de Hardware: Ambas controladoras (Controladora A y B) y el backplane de discos del HPE MSA 2060 se encuentran en estado óptimo.
  • Capa de Hipervisores VMware: Todos los datastores VMFS montados sobre este almacenamiento están en línea en los servidores ESXi, sin cortes de I/O, sin bloqueos de lectura/escritura ni desconexión de máquinas virtuales.
  • Prueba de Capa 3 (ICMP): La prueba de ping continuo desde el servidor Zabbix (172.30.20.61) hacia la IP de gestión del storage (172.30.70.135) arrojó 0% de pérdida de paquetes y 1.0 ms de tiempo de respuesta.
  • Causa Raíz Identificada: La sonda web HTTP de Zabbix utiliza el puerto TCP 443 para consultar la API de gestión. El firewall FortiGate descarta estos paquetes por regla Implicit Deny al cruzar entre zonas.

3.2. Acciones Ejecutadas & Comentario Registrado

Dado que la habilitación del puerto 443 requiere una solicitud de cambio de red (formalizada mediante el expediente MIL-PND-001), se desactivó temporalmente el trigger en el host para evitar el envío de alertas falsas a la guardia:

Comentario de Auditoría en Zabbix (Evento 174422629):
"Falso positivo de hardware. Storage físico y datastores VMware ESXi 100% operativos (0% drop ICMP, latencia 1ms). La recolección de métricas HTTP/REST vía TCP 443 se encuentra bloqueada por regla de firewall FortiGate (Implicit Deny). Se inició solicitud de habilitación de firewall MIL-PND-001. Se deshabilita temporalmente el trigger en este host para evitar alertas P1 redundantes hasta la ejecución del cambio de red." 
// Comandos ejecutados vía initMAX Zabbix MCP Server:
event.acknowledge({ "eventids": ["174422629"], "action": 6, "message": "Falso positivo de hardware..." });
trigger.update({ "triggerid": "29355", "status": "1" }); // Deshabilitado solo en host 10727
